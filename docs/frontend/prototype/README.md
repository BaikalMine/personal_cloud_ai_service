# AI Gateway: interactive design concept

Open `index.html` directly in a browser. No server, account or GPU is required.

This is a standalone proposal, not a production implementation. All users,
jobs, quotas and captions are demonstration data. Actions only change local
prototype state. No request is sent to Gateway, ComfyUI or a training agent.

Surfaces: creation studio, media library, task queue, LoRA dataset editor and
administrative users. Themes: system, light and dark. The prototype uses the
repository's Manrope fonts and a pinned Lucide build (ISC license).

The full functional plan is in `../../PRODUCT_ROADMAP_2026-09-05.md`; the design
specification is in `../REDESIGN_2026-09-05.md`.

## Scope

Theme and generation draft/caption edits persist in this browser's local
storage. This only demonstrates intended recovery behavior, not the planned
server-side durability. Reference picking, optional processing, prompt review,
library filtering, user editing and queue cancellation are interactive.
Training and generation buttons show a preview confirmation, never run jobs.

## Verification

Nine jsdom interaction tests pass. They cover routes, themes, draft/review,
video modes and active references, optional processing, library reuse, caption
isolation/trigger normalization, user quotas and queue cancellation.

Run from the repository root (test dependencies are isolated and ignored):

```powershell
pnpm --dir node_modules/.design-verify add jsdom@26.1.0 --ignore-scripts
node --test docs/frontend/prototype/verify.cjs
```

This is DOM verification, not visual QA. The available in-app browser blocked
the local `file://` URL, so no rendered screenshots, overflow measurements or
native keyboard/dialog checks are claimed for this new prototype. Before
implementation, open the HTML in a regular browser and inspect both themes at
390, 768, 1440 and 1920 px, plus a 320 px stress case.
