# Память и медиа-путь Gateway

Документ описывает контракт этапа G1.4: как Gateway принимает, архивирует, шифрует и выдаёт большие изображения и видео без пика памяти, пропорционального размеру файла.

## Ограничения

| Операция | Ограничение |
| --- | ---: |
| Загрузка изображения | 128 МиБ |
| Загрузка аудио | 32 МиБ |
| Загрузка видео | 512 МиБ |
| Один архивируемый результат | 512 МиБ |
| Суммарные медиа пользователя | 512 МиБ |
| Только отпечаток результата | до 2 ГиБ |
| Блок шифрования в PostgreSQL | 1 МиБ |
| Byte-budget процесса по умолчанию | 256 МиБ |

`MEDIA_INFLIGHT_LIMIT_MB` задаёт общий логический бюджет параллельных операций. Допустимый диапазон — 64–2048 МиБ. Операция, которая не помещается вместе с уже активными, получает контролируемый отказ вместо выхода контейнера за лимит RAM.

## Поток данных

1. Multipart переписывается в `MEDIA_SPOOL_DIR` без `io.ReadAll`; в памяти остаётся только заголовок до 1 МиБ для проверки сигнатуры.
2. Ответ ComfyUI хэшируется во время записи в spool. Результат больше архивного лимита не остаётся во временном файле, но получает SHA-256 для контролируемой очистки.
3. Архивируемое медиа шифруется блоками по 1 МиБ. Каждый блок использует собственный nonce и AAD с идентификатором медиа и номером блока.
4. В PostgreSQL строка `content_media` хранит метаданные, а `content_media_chunks` — блоки `chunked_v1`. Старые строки `inline_v1` остаются читаемыми.
5. Для просмотра блоки последовательно расшифровываются в spool. `http.ServeContent` получает seekable-файл и поддерживает Range для видео.
6. Текущий ещё не архивированный результат передаётся напрямую от ComfyUI в браузер с пробросом Range, без промежуточного `[]byte`.
7. При повторном использовании фото spool собирается в multipart-spool; крупный `bytes.Buffer` не создаётся.
8. Vision-референсы больше 1536 пикселей по длинной стороне уменьшаются перед base64. JPEG кодируется с quality 84; изображения больше 36 Мп отклоняются до полного decode.

Spool-файлы создаются с правами `0600`, удаляются при успехе, ошибке и отмене, а остатки после аварийного завершения очищаются при старте Gateway. В Docker используется отдельный volume `gateway-spool`; `/tmp` остаётся небольшим и `noexec`.

## Измерение

Команда:

```powershell
.\scripts\benchmark-media.ps1
```

Контрольный прогон 1 сентября 2026 года, Ryzen 7 5700X, Linux/amd64 container, `-benchtime=1x`:

| Benchmark | 8 МиБ | 32 МиБ | 64 МиБ |
| --- | ---: | ---: | ---: |
| AES-GCM chunk stream | 2 108 704 B/op | 2 111 008 B/op | 2 114 080 B/op |
| Archive spool | 37 344 B/op | 37 072 B/op | 37 344 B/op |

Аллокации AES-GCM остаются около 2,1 МиБ, а spool — около 37 КБ независимо от размера файла. Число небольших служебных аллокаций может расти с количеством блоков, но их суммарный объём не растёт вместе с payload.

Legacy `inline_v1` при первом чтении всё ещё требует один plaintext-буфер размером с старую запись. Этот путь ограничен byte-budget и постепенно исчезает вместе со сроком хранения старых медиа; все новые архивы записываются как `chunked_v1`.

## Диагностика

Prometheus `/metrics` показывает:

- количество, байты и длительность операций по stage/outcome;
- текущий byte-budget, high-water mark и число отказов;
- histogram размеров и длительности.

Для локального профиля нужно временно установить `PPROF_ENABLED=true`. Маршруты `/debug/pprof/` регистрируются только на административном listener и дополнительно ограничены административной сетью. После снятия профиля настройку следует вернуть в `false`.
