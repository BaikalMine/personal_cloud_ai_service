# Наблюдаемость Gateway

Gateway связывает один запуск генерации через все подсистемы без ручного
сопоставления времени и строк логов.

## Идентификаторы

- `request_id` относится к одному HTTP-запросу и возвращается клиенту в заголовке `X-Request-ID`.
- `correlation_id` создаётся для durable generation job и сохраняется во всех связанных записях.
- `generation_job_id` связывает таблицы по внешнему ключу; `public_id` используется в административном URL.
- `prompt_id` является идентификатором очереди ComfyUI и входит в ту же трассу после успешной отправки workflow.

Логи Gateway пишутся в JSON и включают доступные `request_id`,
`correlation_id`, `generation_job_id` и `prompt_id`.

## Постоянные измерения

`service_observations` хранит компонент, операцию, результат, задержку,
технический код ошибки и связь с генерацией. `gateway_observations` каждые 30
секунд сохраняет активные и просроченные задания, leases майнинга, backlog
проверки текста и медиа, размер БД и возраст последнего успешного cleanup.
Обе таблицы используют `HOST_METRIC_RETENTION` и очищаются общим retention
worker.

## Интерфейсы

- `/admin/metrics` показывает успешность по workflow/модели, p50/p95 очереди и выполнения, последние ошибки, задержки зависимостей, readiness и фоновые задачи с отклонениями.
- `/admin/jobs/{public-id}` показывает переходы состояния и все связанные вызовы, прокси-запросы, аудит, AI-контент и mining lease.
- `/readyz` возвращает HTTP `503` только при недоступной БД. Ошибка необязательной зависимости даёт `degraded: true` при HTTP `200`.
- `/metrics` экспортирует backlog, размер и рост БД, показатели генераций, готовность зависимостей и `gateway_service_latency_ms` histogram.

Страница наблюдаемости строится по сохранённым данным и остаётся полезной после
перезапуска Gateway. In-memory histogram начинается заново при перезапуске, а
исторические p50/p95 продолжают читаться из PostgreSQL.
