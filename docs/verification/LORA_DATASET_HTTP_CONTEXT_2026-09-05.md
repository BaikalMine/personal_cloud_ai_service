# F02/F03: редактор датасета по HTTP/IP

При полном UI gate по внутреннему HTTP-адресу воспроизведено зависание
редактора на «Загружаем наборы...». Chromium сообщил
`crypto.randomUUID is not a function`; `isSecureContext=false`,
`getRandomValues` доступен. Это дефект ранее добавленного редактора,
который не проявляется на HTTPS или доверенном localhost.

## Исправление

`AIGatewayLoraDataset.createID` использует native UUID, когда он доступен,
иначе получает 16 случайных байт через `crypto.getRandomValues` и кодирует
их в 32 hex-символа. Служебные ID непрозрачны для API и такой формат разрешён
действующим валидатором. `Math.random`, часы и снижение случайности не нужны.

Один генератор используется контроллером набора, редактором и применением
подписей. Существующие сохранённые ID не преобразуются. Нового скриптового
маршрута или миграции БД нет; порядок загрузки двух state-модулей сохранён.

## Проверки

- Три новых JS-теста: native UUID, все 128 случайных бит без UUID,
  инициализация контроллера и применение подписи в browser-like окружении.
- Полный набор JS: 68 успешных, 0 ошибок.
- Новый Playwright-сценарий убирает `randomUUID`, сохраняет два изображения
  с подписями, перезагружает страницу и проверяет сохранность и отсутствие
  исключений. Сценарий включён на всех четырёх viewport.
- Итоговый полный UI gate по HTTP/IP: 96 успешных, 72 предусмотренных
  пропуска desktop-only дублей, 0 ошибок. Эталоны LoRA не менялись.
  Проверены сохранение, reload, версии, ZIP, 100 фото и восстановление captions.
  Отчёт: `artifacts/playwright/f04-policy-final-http/report/index.html`.

Production не обновлялся. Для выпуска нужна сборка Gateway со свежими
embedded JS; перезапуск ComfyUI или агента обучения не требуется.
