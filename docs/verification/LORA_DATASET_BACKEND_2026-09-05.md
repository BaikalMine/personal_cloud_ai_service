# F02: серверная часть сохраняемых датасетов

Статус: проверена локально. F02 целиком не завершён, production не обновлён.
Редактор, пользовательский импорт/экспорт ZIP, восстановление версии в новый
рабочий набор и визуальная приёмка остаются в работе следующего этапа.

## Реализованный контракт

- Миграция 54 добавляет рабочие наборы, изображения, шифрованные части файлов,
  независимые версии и ссылки на файлы. Старые миграции не изменяются.
- Рабочий набор хранит порядок кадров, исключённые кадры, ручные подписи,
  триггер, концепт, профиль модели и настройки обучения. Незавершённые подписи
  разрешено сохранять; полнота проверяется отдельно перед обучением.
- Сохранение и удаление набора используют revision/CAS. Чужую или устаревшую
  ревизию нельзя молча перезаписать.
- Изображения загружаются по одному. PNG/JPEG/WebP полностью декодируется до
  записи в БД; одного корректного заголовка недостаточно. Пределы: 24 МБ,
  256..16384 пикселей на сторону, 32 МП. Декодирование резервирует память через
  существующий общий media limiter. При занятости возвращается 429.
- Изображения сохраняются зашифрованными частями до 1 МБ. AAD связывает часть
  с конкретным asset ID и индексом, при чтении проверяются длина и SHA-256.
  Локальный spool используется только для временной обработки и архива агента.
- Повторный SHA-256 в пределах одного владельца не копирует файл повторно.
  Повторная загрузка обновляет срок для ещё не прикреплённого файла, не меняя
  дату создания. Чужие изображения/наборы не доступны даже через прямой ID.
- Перенос собственного фото из AI-контента не требует скачивания на устройство.
  После переноса срок хранения исходной галереи больше не управляет этой копией.
- Предупреждения: точные дубликаты, пустая подпись включённого кадра, изображение
  меньше рабочего разрешения. Семантическая похожесть и фон пока не оцениваются.
- Неизменяемая версия содержит manifest и его SHA-256, но ссылается на те же
  файлы. Повторное создание той же ревизии возвращает существующую версию.
- Новый запуск получает только включённые кадры из зафиксированной версии.
  Подписи нормализуются существующей функцией добавления триггера. В задание
  записываются ID и SHA-256 версии; они доступны в JSON истории обучения.
- Архив собирается последовательно: одновременно материализуется одно фото.
  Изменение или удаление рабочего набора не меняет уже поставленный в очередь ZIP.
  Ошибка постановки задания удаляет временный архив.
- Старый multipart-путь обучения продолжает работать без dataset snapshot.

## API

Все маршруты требуют авторизованного пользователя с правом обучения LoRA
или администратора. Владение наборами/файлами проверяется отдельно.
POST использует `X-CSRF-Token`, связанный с cookie текущей сессии.

| Маршрут | Действие |
| --- | --- |
| `GET /api/lora-datasets` | Список наборов, использование хранилища |
| `POST /api/lora-datasets` | Создать пустой набор с manifest v1 |
| `GET /api/lora-datasets/{id}` | Manifest, ревизия, файлы и предупреждения |
| `POST /api/lora-datasets/{id}/save` | Сохранить manifest с ожидаемой ревизией |
| `POST /api/lora-datasets/{id}/delete` | Удалить рабочий набор по ревизии |
| `POST /api/lora-datasets/{id}/assets` | Multipart с одним полем `image` |
| `POST /api/lora-datasets/{id}/reuse` | Импорт своего `media_id` из AI-контента |
| `GET /api/lora-datasets/assets/{id}` | Получить своё изображение |
| `POST /api/lora-datasets/{id}/versions` | Зафиксировать ревизию |
| `GET /api/lora-datasets/versions` | Список версий, опциональный `dataset_id` |
| `GET /api/lora-datasets/versions/{id}` | Получить версию и manifest |
| `POST /api/lora-datasets/versions/{id}/delete` | Удалить неактивную версию |
| `POST /api/lora-datasets/{id}/train` | Поставить обучение ревизии в очередь |

Загрузка и reuse возвращают asset ID; редактор должен затем сохранить его
в manifest. Незавершённая загрузка не меняет текущий список кадров.

## Хранение и очистка

Пределы: 20 рабочих наборов и 100 версий на пользователя, до 100 кадров и
512 МБ в наборе, до 2 ГБ уникальных исходных файлов на пользователя.

Рабочий набор хранится 30 дней после изменения. Неиспользуемая версия хранится
30 дней после создания/повторного выбора той же ревизии. Версия с любой записью
обучения автоматически не удаляется, включая завершённую запись. Удаление
версии вручную блокируется только при активном обучении. При удалении версии
из завершённой истории убирается ссылка, но остаётся SHA-256.

Файл без ссылок удаляется не раньше 24 часов после последней загрузки/reuse.
Сборщик запускается каждые 15 минут ограниченными порциями по 100 объектов.
Очистка использует блокировки и повторную проверку ссылок в отдельном SQL
statement; параллельное сохранение или постановка обучения не теряет файлы.

- `go test ./...`: успешно.
- `go test -p 1 -count=1 ./internal/database ./internal/store ./internal/gateway`
  с `TEST_DATABASE_URL` на отдельной tmpfs PostgreSQL 16: успешно.
- `node --test internal/gateway/testdata/js/*.test.cjs`: 51/51.
- Миграция 54 проверена с чистой схемы и повторным идемпотентным запуском.
- Store: восемь конкурирующих сохранений, один победитель; foreign IDs;
  дедупликация; rollback оборванного файла; квоты 20 наборов/100 версий;
  повторное создание версии на границе квоты; сроки хранения; удаление
  рабочего набора с активной версией; сохранение hash в истории после удаления.
- HTTP: CSRF; владение; точное сохранение ручных подписей; состояние excluded;
  PNG размером больше одной части; повторная загрузка; повреждённый/маленький
  файл; восстановление байт; шифрование подписей и фото; очистка spool при
  ошибке расшифровки; перенос из галереи и независимость от её удаления.
- Запуск: подставной HTTP-агент отдавал только профили. Создана локальная запись
  очереди, проверены десять ZIP-записей для пяти включённых кадров. Триггер стоит
  первым, исключённый кадр отсутствует, дальнейшая правка подписи не меняет ZIP.
  Повторный запуск при активной задаче отклонён, его архив удалён.

Реального обучения, обращения к GPU, остановки ComfyUI или изменения production
не было. Frontend в этом этапе не менялся; Playwright для нового редактора ещё
не выполнялся. Полная приёмка F02 этим протоколом не заявляется.
