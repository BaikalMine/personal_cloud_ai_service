# F04: приоритет независимо от майнинга

Статус: код, PostgreSQL и полный UI gate проверены локально.
Production не обновлялся. Это часть F04, не завершение общей GPU-очереди.

## Изменения

- Миграция 58 добавляет `queue_priority` пользователям и приглашениям.
  Исходное значение копируется из прежнего общего флага. Само правило
  `pause_mining_for_quick_generation` не меняется. Повторная миграция не
  перезаписывает уже разделённые настройки.
- Генерация и пакеты передают в ComfyUI новый флаг приоритета. Mining leases
  и зависимости от mining-agent продолжают использовать только правило майнинга.
- Очередь обучения читает `queue_priority`. Привилегия даёт 10 минут
  преимущества по времени ожидания, как в контракте GPU admission;
  достаточно старая обычная задача обходит новую приоритетную.
  Активное обучение не вытесняется.
- Приглашения и права пользователя содержат два независимых переключателя.
  Приоритет доступен и аккаунту только с обучением LoRA.
- Переключатель в шапке меняет только приоритет администратора.
  Его правило майнинга редактируется отдельно в профиле.
- Формы версии 2 передают параметры независимо. Старые открытые формы без
  версии сохраняют прежний смысл общего переключателя при отправке.
- Автоматическая пауза для обучения LoRA остаётся обязательной, как раньше;
  пользовательское правило майнинга относится к генерации и ассистенту.

## Выпуск и ограничения

- Нужны новая сборка Gateway и миграция БД. ComfyUI, Windows-agent и
  training-agent этим изменением не обновляются и не перезапускаются.
- Старый Gateway отвергает БД с более новой версией схемы. Нельзя обещать
  rollback простой заменой бинарника: нужен согласованный план восстановления.
- Разделение настроек само по себе не является GPU mutex. Четыре рабочих
  пути ещё не подключены к общему admission; mixed-load и внешние процессы
  требуют отдельной приёмки. Aging сейчас подключён к очереди обучения;
  общая дисциплина всех работ остаётся открытым пунктом F04.
- Исправление HTTP/IP редактора датасетов, найденное при UI gate, описано
  отдельно в `LORA_DATASET_HTTP_CONTEXT_2026-09-05.md`.
