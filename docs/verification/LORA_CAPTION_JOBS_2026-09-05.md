# F03: устойчивые описания кадров LoRA

Дата: 5 сентября 2026 года. Статус: реализовано, проверено локально;
развёртывание в production остаётся отдельным этапом.

## Реализация

- Миграция 55 создаёт `lora_caption_jobs`. Задание содержит owned asset,
  идентификатор кадра, версию подписи, trigger/concept и фиксированный текст
  инструкции с SHA-256. Входные данные и результат шифруются существующим cipher.
- Весь выбранный набор ставится в очередь одной транзакцией. Повтор одного
  запроса и конкурентные запросы к активному кадру не создают второй run.
  Лимиты: 100 активных и 500 хранимых заданий на пользователя.
- Worker получает одну фотографию, а не весь датасет. PostgreSQL session lock
  удерживается на протяжении вызова модели. Другой процесс Gateway не забирает
  живое задание. После потери прежнего обработчика run восстанавливается;
  старый run token не может записать результат поверх нового.
- 408/429/5xx и временные сетевые ошибки повторяются, максимум три попытки.
  Пользователь может отменить серию, один кадр или повторить выбранную ошибку.
  Heartbeat прерывает запрос при отмене, потере DB-соединения или отозванном доступе.
- Готовый ответ хранится отдельно от редактируемой подписи. Редактор применяет
  его только при совпадении кадра, asset, версии и текста подписи, trigger/concept.
  Ручная правка, включая ввод и возврат прежнего текста, меняет revision.
  Применённый job ID сохраняется с подписью, поэтому reload не применяет ответ дважды.
- Закрытие страницы не отменяет серверные задания. После открытия, reconnect и
  возврата из back-forward cache редактор получает существующие задания.
  При ошибке опроса сохраняет последние состояния и показывает обратный отсчёт.
- Ошибочные и отменённые задания очищаются через 24 часа; завершённые через
  30 дней. Активные задания не удаляются по возрасту. Ссылки заданий защищают
  необходимые фото от сборки неиспользуемых файлов.
- Старый `/api/lora-training/caption` сохранён для уже открытых страниц, но
  использует новый worker. Новый редактор передаёт ID кадров без повторной
  загрузки фото с сервера в браузер и обратно.

## Проверки

- `go test -p 1 ./...`: все пакеты прошли.
- Отдельный PostgreSQL 16 на tmpfs, без production-данных: database/store/gateway
  с `-p 1 -count=1` прошли. Дополнительный F03 integration прогнан повторно.
- Integration: восстановление run в новом App, неизменяемая инструкция, ровно
  одно фото в вызове модели, максимум один одновременный вызов, восемь
  конкурентных enqueue, 504, отмена активного запроса, отдельный retry, отмена
  серии, отклонение устаревшего token, ownership и CSRF существующего API.
- Проверены 100 заданий, атомарный отказ при 101-м, конфликт retry старой версии
  с активной новой, сохранение единственной ссылки на фото и его очистка после
  удаления всех просроченных заданий.
- JS: 65 успешных тестов, включая семь новых проверок reconcile/poll/reconnect.
  Общий `scripts/test.ps1` запускает все `*.test.cjs`, включая F02 и F03.
- Полный Playwright gate: 84 успешных, 72 штатных пропуска desktop-only повторов,
  0 ошибок, 5,3 минуты. Эталоны не изменялись. Все четыре viewport:
  390/768/1440/1920; текущая production-тема.
- После финальных правок возврата страницы и синхронизации поля выполнен
  повторный фокусный прогон: 17 успешных, 15 штатных пропусков, 0 ошибок.
- Браузерные сценарии: серия после закрытия страницы, ручная подпись во время
  ответа, повтор конкретной ошибки, отмена одного кадра/серии, 504 с отсчётом,
  сохранённый результат после reload, отсутствие повторной загрузки файлов.
- Просмотрены desktop/mobile screenshots ошибки: состояние и действие находятся
  у соответствующего кадра, подпись остаётся редактируемой, переполнения нет.

Локальные артефакты: `artifacts/playwright/f03-captions/`,
`artifacts/playwright/f03-full-gate/`, `artifacts/playwright/f03-final-captions/`.
UI-preview: `http://127.0.0.1:18085/preview/lora-training`, только fixture-данные.

## Исправление проверки F02

Preview отдавал все JS-файлы, а production использует явный список маршрутов.
В списке не было `lora-dataset-state.js`, `lora-dataset-editor.js` и
`vendor/lucide.js`. Маршруты и включение в AssetVersion исправлены.
Тест `TestEveryEmbeddedJavaScriptHasAProductionRoute` теперь проверяет каждый
embedded JS; HTTP-тест проверяет фактическую выдачу зарегистрированных файлов.
Прежний preview-прогон F02 сам по себе не доказывал доступность этих файлов
в production. F02 ещё не разворачивался, исправление входит в предстоящий выпуск.

## Границы

Реальные GPU-генерации, обучение и оценка точности caption-модели здесь не
запускались. Модель заменена локальным HTTP-стендом; браузер использует fixtures.
Это доказательство сохранности и переходов, а не качества описания внешности.
Общая очередь между генерацией, обучением и ассистентами относится к F04.
Блокировка caption-worker не заменяет эту очередь.

Новая светлая/тёмная оболочка D01/D02 и паспорт LoRA D07 не внедрены этим этапом.
ComfyUI, production и пользовательские контейнеры не останавливались.
