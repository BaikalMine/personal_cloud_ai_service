# F04: отдельный исполнитель запросов к модели

Дата: 6 сентября 2026 года. База: `a739818`.
Статус: исполнитель и его клиент реализованы, локальная проверка выполнена.
Подключение к обработчикам ассистентов и выпуск пока не выполнены.

Последующий этап: [описания LoRA подключены к исполнителю](LORA_CAPTION_INFERENCE_RUNTIME_2026-09-06.md).
Границы ниже описывают исходный этап; промпт-ассистент генерации и выпуск
по-прежнему остаются открытыми.

## Реализация

- Миграция 63 создаёт `gpu_inference_requests`. ID запроса совпадает с ID GPU-работы.
  Принятие запроса и привязка исполнителя фиксируются одной транзакцией.
- `internal/inference.Client` сохраняет зашифрованный запрос и получает ответ по
  тому же ID. Уход клиента отменяет ожидание, но не перезапускает и не отменяет
  уже принятую работу. Повтор с изменённым содержимым, токеном или timeout отклоняется.
- `cmd/inference-worker` работает отдельным процессом и отправляет запрос только
  после постоянного маркера запуска. Два worker не отправляют одну работу дважды.
  Процесс не запускает/останавливает Ollama, ComfyUI или майнер.
- Подтверждение `done=true` в полном успешном ответе модели и зашифрованный ответ
  сохраняются вместе. Сбой БД повторяет только эту транзакцию, не запрос к модели.
  Существующее восстановление GPU использует сохранённое подтверждение.
- Отмена до отправки запрещает запуск и сохраняет доказательство отсутствия
  отправки. Отмена после запуска не выдаёт завершение без ответа модели.
- HTTP 504, разрыв соединения, redirect, некорректный/слишком большой ответ или
  `done=false` оставляют выполнение неподтверждённым. Redirect не пересылает POST.
- Просроченный Gateway-токен не даёт повторно отправить принятую работу.
  Завершённый ID нельзя вернуть в очередь; поздний ответ принят только от
  записанного исполнителя. Старый прямой обработчик не может подтвердить за него
  завершение или снять GPU по неподтверждённому результату.
- Опрос статуса не читает из БД изображения и полный промпт. Полный запрос читает
  только получивший задание worker. Запрос очищается после обработки; содержимое
  ответа удаляется через 24 часа. Для прерванного исполнителя входные данные тоже
  очищаются по сроку. Минимальная запись ID/отправки остаётся защитой от повтора.
- Шифрование использует существующий content cipher с разными AAD для запроса
  и ответа, привязанными к ID. Проверяется также hash расшифрованного запроса.

## Проверка

Использованы отдельная PostgreSQL 16 на tmpfs и HTTP-фикстуры. Рабочие GPU,
пользовательские материалы и production-БД не использовались.

- Полный `go test -p 1 -count=1 ./...` с PostgreSQL: прошёл.
- Потеря ожидающего клиента, новый экземпляр клиента и получение прежнего ответа:
  ровно один вызов модели, сохранены текст и изображение в исходном запросе.
- 16 конкурентных принятий одного ID и восемь конкурентных worker:
  одна запись и один вызов модели.
- Неверный токен, несовместимый вид GPU-работы, незаконченная подготовка,
  отмена, просроченное резервирование и изменение содержимого: отклонены.
- Проверены 504, redirect, повреждённый/неполный/слишком большой ответ и
  оставленный прежним исполнителем маркер запуска. Автоматической повторной
  отправки или освобождения GPU нет.
- Позднее подтверждение после истечения владения и отмены сохраняется; неправильный
  токен исполнителя не принимается. Удаление ответа по сроку не стирает доказательство.
- Искусственный отказ SQL-триггера откатывает одновременно результат и GPU evidence.
  Рабочий цикл повторяет сохранение после снятия отказа; вызов модели остаётся один.
- Подтверждённая работа освобождает связанный mining lease через существующий
  транзакционный путь. Реальный майнер в этой проверке не запускался.
- `go test -p 1 -count=10 ./internal/inference`: прошёл, 45.664 секунды.
- `go vet ./...`: прошёл.
- Cross-build `cmd/inference-worker` для Windows/amd64: прошёл, без запуска.
- `git diff --check`: прошёл. UI/JS не менялись; браузерные проверки не запускались.

Первый адресный запуск нашёл ошибку компиляции: проверка hash была размещена после
ответа, а не перед отправкой. Перенесена в проверку расшифрованного запроса;
последующие адресный и полный прогоны прошли.

## Запуск и границы этапа

Команда: `go build ./cmd/inference-worker`. Процесс использует `DATABASE_URL`,
`SESSION_SECRET` и `OLLAMA_UPSTREAM`. Схема должна быть установлена согласованным
выпуском Gateway; worker сам миграции не запускает. Compose, системные службы и
настройки production этим изменением не затронуты.

Обязательный остаток F04:

1. Подключить подготовку/разбор запросов обоих ассистентов к этому клиенту,
   заменив прямую отправку и связав ID с постоянной пользовательской задачей.
2. Восстанавливать описание кадра по прежнему запросу после смены caption run token,
   а не создавать новую генерацию. Сохранить права, отмену, trigger и ручные подписи.
3. Сделать асинхронный API и восстановление панели промпт-ассистента, включая
   событие AI-контента и возврат готового результата после закрытия страницы.
4. Если сам исполнитель погиб после отправки в Ollama, его маркер не доказывает
   завершения. Нужен проверяемый исход со стороны модельного процесса; такой запрос
   здесь не повторяется и не освобождает GPU автоматически.
5. Подготовить согласованный запуск worker, наблюдаемость/готовность, backup и
   очистку технических записей, затем смешанные и реальные GPU-проверки и выпуск.

Этот этап не закрывает F04, F07, D06 или общую цель. Уже существующие прямые
запросы не получают восстановление задним числом.
