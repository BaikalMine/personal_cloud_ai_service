# F04: постоянные задания промпт-ассистента

Дата: 6 сентября 2026 года. База: `139dc9d`.
Статус: серверный API и worker реализованы и проверены локально. Панель ещё
использует прежний синхронный маршрут. Production не изменён.

## Реализация

- Миграция 65 добавляет `prompt_assistant_jobs`: зашифрованный снимок запроса,
  исходный промпт и контекст панели, сохранённый результат, состояние отмены,
  токен текущего обработчика и привязка к постоянному inference ID.
- `POST /generate/prompt-assistant/jobs` сохраняет источник и место в GPU-очереди
  одной транзакцией и возвращает 202. Тот же `request_id` с тем же снимком
  возвращает прежнее задание. Другой снимок или владелец получают конфликт.
  Истёкший ID нельзя использовать заново даже после удаления source-записи:
  остаётся GPU-запись, запрещающая повторное использование идентификатора.
- `GET /generate/prompt-assistant/jobs?id=...` возвращает состояние только
  владельцу с соответствующим правом генерации. `POST` на `/jobs/cancel`
  проверяет прежние правила входа/CSRF и сохраняет намерение отмены.
- HTTP освобождает локальный слот и изображения после сохранения. Worker
  использует общий GPU-допуск, передаёт снимок отдельному inference-исполнителю
  и дальше читает прежний ID, без повторного обращения к модели. Большое тело
  запроса не загружается при чтении статуса или выборе следующего задания;
  после передачи оно удаляется из source-записи.
- Передача inference, привязка source, GPU dispatch и данные о приостановке
  майнинга фиксируются вместе. Готовый результат, запись AI-контента и метрики
  ассистента также фиксируются одной транзакцией. Ошибки записи не оставляют
  половину результата и не вызывают повторный запуск модели.
- Очередь обновляет сроки готовности принятых задач и актуальный приоритет.
  Время ожидания не включается в модельную latency: используются сохранённые
  отметки начала/завершения исполнителя.
- Отмена до отправки работает при выключенном inference-worker. После отправки
  отменяется пользовательский результат, но GPU удерживается до подтверждения
  завершения. HTTP 504 и пустой список моделей не считаются таким подтверждением.
- Новый source-токен может отозвать старый допуск только до принятия inference
  и после завершения подготовки ресурсов. `preparing_resources` не освобождается:
  ранее отправленные команды хоста ещё могут выполняться.
- Повреждённое тело запроса завершается ошибкой без вызова модели. Просроченное
  задание отменяется до расшифровки метаданных; повреждение метаданных не мешает
  удалению source-записи. Уже отправленная неподтверждённая работа сохраняет
  отдельную GPU/inference-запись.
- Ограничения новой очереди: четыре незавершённых задания на пользователя,
  100 принятых за последние сутки и 512 MiB суммарных source-тел. Это лимиты
  промпт-ассистента, не расход лимита генерации фото/видео. Source хранится
  24 часа от принятия; очистка удаляет терминальные просроченные записи.

## Проверка

Использованы PostgreSQL 16 на tmpfs и локальные HTTP-фикстуры. Production-БД,
реальные фотографии, Ollama, ComfyUI, GPU и майнер не использовались.

- HTTP 202, повторное получение, конфликт снимка, изоляция владельцев,
  восстановление чтения при выключенном rollout-флаге и отмена: прошли.
- Восемь конкурентных попыток сохранить один ID создают одну source-запись;
  предел очереди и отклонение пустого worker-токена: проверены.
- Перезапуск Gateway после готового ответа, смена текущей модели, отсутствие
  свободных локальных слотов/медиабюджета: ответ восстанавливается из БД,
  вызов модели, событие и запись метрик остаются единственными.
- Ошибка SQL при связывании inference откатывает весь приём. Ошибка вставки
  метрик откатывает и событие AI-контента, и terminal source. Повторная обработка
  завершает тот же запрос, модель не запускается заново.
- Отмена до и во время вызова, поздний ответ, отзыв права перед запуском,
  неизвестный исход HTTP 504: проверены.
- Восстановление `reserved`/`resources_ready`, запрет старого токена,
  сохранение `preparing_resources`, приоритет до GPU-допуска, обновление
  queue intent, повреждённый запрос, expiry и tombstone: проверены.
- Полный `go test -p 1 ./... -count=1` с отдельной PostgreSQL: прошёл;
  gateway 27.168 с, inference 4.940 с, store 2.282 с.
- Три повтора всех `TestDurableAssistant` в gateway: прошли, 12.894 с.
- `go vet ./...`, сборка `cmd/inference-worker` для Windows/amd64 и
  `git diff --check`: прошли.
- Шаблоны/CSS/JS в этом этапе не менялись; браузерная приёмка не выполнялась.

## Выпуск и остаток

`PROMPT_ASSISTANT_DURABLE_JOBS=true` разрешает новые POST в асинхронный API.
По умолчанию false. Нужны миграция 65 и совместимый отдельный inference-worker.
Принятые задания продолжают обрабатываться независимо от этого переключателя.
Прежний `/generate/prompt-assistant` пока сохранён для действующей панели.

Следующий этап: подключить новый API к панели, сохранять ID при уходе/перезагрузке,
восстанавливать опрос с отсчётом повторного соединения, показывать отмену и не
применять ответ к изменённому пользователем контексту. Нужны браузерные проверки.

F04 остаётся открытым: модельное подтверждение после падения самого исполнителя,
внешние запуски GPU, смешанная нагрузка, реальные GPU-сценарии и согласованный
выпуск F14 этим этапом не решены. Миграция и код в production не развёрнуты.
