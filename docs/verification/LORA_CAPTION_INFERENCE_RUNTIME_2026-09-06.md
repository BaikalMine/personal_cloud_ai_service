# F03/F04: описание LoRA через постоянный исполнитель

Дата: 6 сентября 2026 года. База: `94ad75f`.
Статус: подключено к рабочему caption-worker Gateway за переключателем выпуска;
production не изменён. Общая очередь F04 этим этапом не закрывается.

## Реализация

- Миграция 64 связывает `lora_caption_jobs` с постоянным inference ID и
  зашифрованным контекстом разбора. Привязка задания, принятие запроса и передача
  GPU фиксируются одной транзакцией. Проверяются текущий caption run token,
  владелец и отсутствие отмены.
- Подготовка запроса и разбор ответа вынесены из прямого HTTP-вызова. Инструкция,
  пользовательский trigger, единственное изображение, модель и её параметры
  сохраняются в момент отправки. После перезапуска используется прежний контекст,
  даже если текущая модель или инструкция изменились. Изображение не дублируется
  в метаданных разбора.
- Gateway после передачи освобождает локальный слот и буферы изображения.
  Следующие проходы читают прежний ID, не загружают фото и не запускают модель
  повторно. Ожидание не расходует попытки. Оборванный caption-handler с исчерпанным
  счётчиком также восстанавливает связанную работу.
- Готовый ответ восстанавливается при выключенном переключателе новых отправок
  или отсутствии текущей vision-конфигурации. Новые несвязанные задания без
  vision-модели не запускаются.
- Отмена/отзыв права до dispatch запрещают отправку. Gateway может отменить
  такую работу и при недоступном inference-worker. Запущенный запрос не считается
  завершённым из-за отмены; готовый поздний ответ не применяется к подписи.
- Явный повтор отменённого/ошибочного задания разрешён только после известного
  исхода старого запроса. При неподтверждённом исходе API возвращает 409 с
  объяснением; повторная генерация не запускается.
- Метаданные привязки не выдаются в публичном представлении caption-задания.
  Действующий интерфейс опроса, сопоставление caption revision и защита ручных
  правок сохранены. Шаблоны, CSS и JavaScript не изменялись.

## Проверка

Отдельная PostgreSQL 16 на tmpfs, фиктивные HTTP-ответы модели, без production-БД,
реальных фотографий, GPU, обучения, ComfyUI и майнера.

- Полное совпадение подготовленного и прямого запросов, восстановление парсера
  из сериализованных метаданных: проверено.
- Восстановление после смены Gateway/run token/модели, пять циклов ожидания,
  исходная revision подписи и один trigger в начале: проверено, один вызов модели.
- HTTP 504 не создаёт новый запрос, не расходует попытки и не освобождает GPU:
  проверено. Это сохранение неизвестного состояния, а не решение исходной 504.
- Отмена до и во время dispatch, в том числе без запущенного executor:
  проверено. Поздний обработчик не записывает ответ, явный повтор после
  подтверждённого исхода очищает старую привязку.
- Отзыв права обучения до отправки и восстановление при выключенной vision:
  проверено.
- Неправильный source token и искусственная ошибка SQL INSERT: проверены;
  ошибка откатывает и caption binding, и GPU dispatch.
- Десять повторов `TestDurableCaption`, `TestGPUInference` и
  `TestInferenceMiningCompletionIntegration` в `internal/gateway`: прошли,
  61.197 секунды.
- После последней правки отмены полный `go test -p 1 -count=1 ./...` с отдельной
  PostgreSQL: прошёл; gateway 22.724 с, inference 4.690 с, store 2.429 с.
- `go vet ./...` и сборка `cmd/inference-worker` для Windows/amd64: прошли.
- 96 JS-тестов и `git diff --check`: прошли. Новых визуальных изменений нет;
  браузерный прогон не выполнялся.

## Выпуск и остаток

`LORA_CAPTION_DURABLE_INFERENCE=true` включает новые отправки через исполнитель.
По умолчанию false до согласованного выпуска. Для включения нужны миграция 64,
совместимые Gateway и `cmd/inference-worker`, одинаковый `SESSION_SECRET` и
правильный `OLLAMA_UPSTREAM`. Уже принятые запросы восстанавливаются независимо
от переключателя. Worker сам миграции не применяет.

Следующий этап: постоянная пользовательская задача промпт-ассистента генерации,
асинхронный API, восстановление панели и единое событие AI-контента. Его текущий
путь пока прямой. Падение самого inference-worker после отправки в модель всё
ещё требует достоверного подтверждения со стороны модельного процесса; таймаут,
возраст записи и пустой `/api/ps` таким подтверждением не являются.

Остаются также готовность/наблюдаемость исполнителя, общая смешанная нагрузка,
внешние задачи, реальные GPU-сценарии и согласованный выпуск F14.
