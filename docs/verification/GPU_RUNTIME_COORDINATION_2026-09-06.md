# F04: подключение общего допуска GPU

Дата: 6 сентября 2026 года. База: `ce3fa1b`.
Статус: этап реализован и проверен локально. Полный F04 и выпуск не завершены.

## Реализовано

- Реальные пути отправки генерации, обучения, описания кадра и улучшения
  промпта получают общий допуск PostgreSQL перед обращением к GPU-исполнителю.
  Генерации сохраняют квоту и ожидающее задание, если GPU занят.
- Приоритет и aging используют общую очередь. Начальная дата ожидающей
  подписи сохраняется при переносе, ожидание не расходует попытки модели.
- Миграция 61 добавляет токен отправки обучения. Новый claim и восстановление
  отзывают старый токен; старый worker не может отправить или повторно поставить
  в очередь новую попытку. Существующие переданные задания не сбрасываются.
- Повторное получение GPU генерацией/обучением требует действующего нового
  source claim и отсутствия маркера отправки. Сама просрочка GPU lease не
  разрешает повторную отправку. Освобождение проверяет source fence под
  блокировкой, включая ещё ожидающую, а не только активную запись GPU.
- Отдельный maintenance worker сохраняет владение длительной генерации и
  обучения. Терминальные source-записи позволяют повторить освобождение.
- Каждый вызов ассистента получает новый внутренний ключ, включая повторы
  описания того же кадра. Подтверждение `done=true` сохраняется отдельно в
  `gpu_work.inference_completion`, поэтому освобождение можно закончить после
  перезапуска. Отсутствие ответа, отмена HTTP и 504 не записывают такое подтверждение.
- Windows training-agent предоставляет авторизованный `GET /v1/activity`.
  Учитываются незавершённые jobs, неподтверждённые процессы и загрузки датасета,
  которые ещё не успели попасть в реестр jobs. Ответ не кешируется.
- Перед новым допуском проверяются очередь ComfyUI, активность training-agent
  и инвентарь загруженных моделей Ollama. Старый/недоступный agent и отсутствующий
  инвентарь не считаются свободным GPU. Поддержана конфигурация только с vision.
- Завершённый вызов сначала освобождает общий GPU, затем пробует вернуть майнинг.
  Общая session advisory lock исключает пересечение допуска нового задания с
  последней проверкой/запуском майнера между экземплярами Gateway.
  Видимая внешняя задача ComfyUI откладывает возврат майнинга, сохраняя запрос в БД.
- Старые переданные задания Gateway и неподтверждённые аренды ассистентов
  не игнорируются при обновлении со старой версии.

## Проверки

Все проверки изолированы: отдельная временная PostgreSQL 16 на tmpfs,
локальные HTTP-фикстуры исполнителей, без доступа к production-БД и GPU.

- Полный `go test -p 1 -count=1 ./...` с `TEST_DATABASE_URL`: пройден.
- `go test -p 1 -count=10 -run
  'TestGPU|TestInferenceMiningCompletionIntegration|TestLoraTrainingHandoffIntegration'
  ./internal/store ./internal/gateway`: десять повторов пройдены. В том числе
  существующий конкурентный тест 32 попыток допуска.
- После добавления vision-only проверки полный Go-прогон повторён: все пакеты
  прошли, включая интеграционные проверки с отдельной PostgreSQL.
- JS: 96 успешных, 0 ошибок и пропусков.
- Сборка `cmd/lora-training-agent` для Windows amd64 с `CGO_ENABLED=0`: пройдена;
  исполняемый файл не устанавливался и не запускался.
- Проверены отказ старого/недоступного агента, внешняя очередь ComfyUI,
  загруженная Ollama, потеря квитанции генерации и обучения, старые source/GPU
  токены, восстановление завершённого inference и ожидание сверх лимита retries.
- Существующие интеграционные сценарии обоих ассистентов и mining leases
  теперь выполняются с включённым координатором, а не с обходящим его nil-полем.
- API активности проверен через реальный HTTP server/client training-agent,
  включая загрузку, заблокированную внутри reader, и отказ этой загрузки.

UI-файлы не менялись; новых визуальных проверок в этом этапе нет.
Это не доказательство реальной скорости, качества генерации или отсутствия
гонок с программами, которые обращаются к исполнителям вне Gateway.

## Обязательный остаток F04

1. Исполнитель с постоянным ID и подтверждением завершения для inference:
   неподтверждённый отправленный запрос сейчас удерживает GPU. Пустой `/api/ps`
   не используется как доказательство его завершения. Нужно также восстановление
   незавершённого резервирования ассистента до отправки и связанного mining lease.
2. Устойчивый асинхронный запуск prompt-assistant и восстановление его ожидания
   в UI. Сейчас HTTP-обработчик ждёт GPU; общий пользовательский раздел задач
   и дальнейшее объединение с F07/D06 не реализованы.
3. Проверить порядок регистрации относительно локальных слотов ассистента,
   приоритет смешанной очереди под реальной нагрузкой и полную отмену пакетов.
4. Внешняя работа ComfyUI/OpenWebUI может стартовать после снимка активности.
   Для строгого исключения нужен общий допуск на стороне исполнителей.
   Аналогично требуется закрыть поздний запуск майнера при потере ответа агента.
5. Дополнить привязку этапа/ID исполнителя в общем GPU-журнале, очистку его
   записей и эксплуатационные действия для неподтверждённых задач.
6. Проверки реального GPU, общей матрицы UI/прав и согласованный выпуск.

Загруженная, но не выполняющая запрос Ollama намеренно считается занятой
для нового допуска: это консервативная защита памяти, а не доказательство
активного inference. Нестандартный keep-alive может увеличивать ожидание.

## Выпуск

Production, рабочие ComfyUI, Ollama, майнинг и Windows-agent не менялись.
До выпуска нужно обновить контракт training-agent `/v1/activity` и пройти
проверку совместимости. Старый Gateway не должен параллельно отправлять
обучение без токенов новой версии. Миграция 61 и новый Gateway не выкладываются
по отдельности от согласованного этапа F14. Этот документ не разрешает
останавливать пользовательские генерации или перезапускать ComfyUI.
